ROOT CAUSE OF FAILURES
─────────────────────
1. Client-side only (no server backing)
2. Cookie set from JavaScript (unreliable)
3. No correlation between cookie and session
4. No CORS/credentials configuration
5. Race condition during page refresh
6. Sessions only in memory, not persisted

HOW IT WORKS NOW
────────────────

Login Flow:
  1. User enters credentials on /login
  2. Frontend calls POST /api/auth/login (credentials: include)
  3. Server verifies email + password
  4. Server creates session object
  5. Server sets HTTP-only cookie via Set-Cookie header
  6. Client receives response + cookies (auto-managed)
  7. Auth context updates React state
  8. Redirect to /dashboard
  9. Middleware verifies cookie exists + session valid
  10. Route access granted

Session Persistence:
  - Browser automatically sends cookies on every request
  - Server validates session on middleware check
  - React state hydrates on page load
  - Works across tabs, refreshes, and devices

ARCHITECTURE COMPARISON
───────────────────────

BEFORE (Broken):
  Client [localStorage] → Middleware [checks cookie] ✗ Race condition
  Problem: No server backing, unreliable cookie

AFTER (Production-Ready):
  Client → Server [/api/auth/*] → Server [Set-Cookie] → Client [auto-store]
  → Middleware [verify cookie + session] ✓ Reliable
  Benefits: Server-backed, secure cookies, proper authorization

SECURITY IMPROVEMENTS
─────────────────────

Before          After
───────         ─────
No backing  →   Server-backed sessions
Plain text  →   HTTP-only cookies (can't be stolen via XSS)
Visible     →   Secure flag (HTTPS only)
No CSRF     →   SameSite=Strict (prevents cross-site requests)
No auth     →   Middleware validates every protected route
Scattered   →   Centralized session state

COOKIE FLAGS EXPLAINED
──────────────────────

HttpOnly:    Can't be accessed by JavaScript (prevents XSS theft)
Secure:      Only sent over HTTPS (prevents man-in-the-middle)
SameSite:    Only sent with same-site requests (prevents CSRF)
Path:        Only sent to /api and subdirectories
MaxAge:      Expires after 24 hours

TROUBLESHOOTING
───────────────

Login doesn't work?
  → Check browser console for errors
  → Open Network tab, retry login
  → Look for 200 response from /api/auth/login
  → Verify user was created in previous registration

Session doesn't persist after refresh?
  → Open DevTools → Cookies
  → Verify jt_session_id exists
  → Try: localStorage.getItem('job_crm:v1:auth:session')
  → Should return valid session object

Still logged in after logout?
  → Clear cookies: DevTools → Cookies → Delete all
  → Try /dashboard - should redirect to /login

API Errors?
  → Check Network tab → Response body
  → Should show { success: false, error: "..." }
  → Compare against error messages in code
